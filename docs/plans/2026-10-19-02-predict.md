# Plan 2: Predict (0.8.0)

> Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** before the owner approves, every run says what the change is likely to affect beyond the files it edits, and what is most likely to regress, with how likely and why. The owner approves with the blast radius in view, and the tester knows where to look.

**Architecture:** the scout already maps the change and, since 0.5.0, the run is sized. Prediction extends that map outward: callers and dependents from the knowledge graph or a reference search, history from `git log`, and past incidents from memory (plan 1). The planner writes it into `approval.md`; the tester turns each high risk into a test. No new agent.

**Depends on:** [Remember](2026-10-19-01-remember.md). **Overview:** [2026-10-19-intelligence-overview.md](2026-10-19-intelligence-overview.md)

## What a prediction looks like

A `## Impact and regressions` section in `approval.md` (standard and deep; one line in quick):

```markdown
## Impact and regressions
Reach: 4 files edited, 11 that use them (graph), 2 screens, 0 endpoints, no data.

| ID | What could regress | Likelihood | Why we think so | Guard |
|---|---|---|---|---|
| R-1 | The phone bottom bar overlaps the last section | medium | `bottom-tabs.tsx` is fixed and the page loses its bottom padding; I-004 was the same overlap on Compare | screenshot at 390 px in the test stage |
| R-2 | Computer layout changes | low | every new class is `max-md:` | screenshot at 1280 px |
```

- **Likelihood is one of low, medium, high**, never a percentage: the number would be false precision.
- **Every row has a "why"** that cites evidence: a graph edge, a file's churn in `git log`, a memory incident ID, or a test that does not cover the path.
- **Every medium or high row has a guard** the run will actually do: a test, a check in review, a screenshot.
- The predictions are copied into `state.md` under `predictions:`, so Learn (plan 4) can score them.

## Risks

- **Noise: a table of generic risks nobody reads.** Guard: evidence required per row, at most 6 rows, and Learn scores them, so vague rows show up as never `caught`.
- **Cost of the history and reach search on a big repo.** Guard: the graph first; `git log` limited to 90 days and the edited files; the scout lists notable dependents, not all.
- **False confidence from "low".** Guard: the summary says plainly that the forecast is a guide; the full test command still runs in every mode but quick.

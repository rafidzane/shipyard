# Plan 1: Remember (0.7.0)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** each project keeps a memory of the decisions it made, the incidents it had and the patterns it follows. Every run reads it before it plans, and adds to it when it finishes, so Shipyard stops re-asking settled questions, re-proposing rejected designs and re-breaking fixed things.

**Architecture:** three Markdown files in the project repo, written only by the orchestrator at the finish and read by the scout at research. No new agent. The files are the interface the next three plans build on.

**Overview:** [2026-10-19-intelligence-overview.md](2026-10-19-intelligence-overview.md)

## The memory

`docs/shipyard/memory/` in the project, committed with the run:

| File | Holds | One entry |
|---|---|---|
| `decisions.md` | Choices the owner made or approved that a future run should not reopen | `- D-007 2026-10-18 (run share-timeout-password-savings): sign-out after 15 minutes idle on every device, enforced on the server. Why: owner's answer. Supersedes: none` |
| `incidents.md` | What went wrong, its cause, and the guard against it | `- I-003 2026-10-18 (run idle-signout-message): idle sign-out lost its message: 401s from refetches redirected first. Cause: apiFetch's own 401 redirect. Guard: markSigningOut(). Files: lib/api.ts, idle-signout.tsx` |
| `patterns.md` | How this project does things, learned from runs and the owner's corrections | `- P-012 (seen 3 runs): phone-only styles use the max-md: variant, the bottom bar's breakpoint` |

Rules:
- **IDs are stable** (`D-`, `I-`, `P-` and a number), so later entries, predictions and approvals can cite them.
- **Each file is capped at 150 entries.** Past the cap, the finish folds the oldest entries in one category into a single summary entry that lists the IDs it replaced. Nothing is dropped without a trace.
- **The owner's edits win.** An entry the owner changed by hand (the run that wrote it is not the last commit to touch that line) is never rewritten; a newer entry may supersede it, citing its ID.
- **What never goes in:** credentials, tokens, personal data, real account emails, customer names, anything from `secrets.ini` or `.env`.

## Risks

- **Memory goes stale** (a decision the code has since moved past). Guard: a decision cites its run and date; the scout reports a decision the code now contradicts as `## Unclear` instead of treating it as settled. Learn (plan 4) retires stale entries.
- **Memory bloats every run's context.** Guard: the cap, the summary fold, and the scout reporting only entries that touch the request.
- **Two runs write memory at once and conflict on merge.** Guard: entries are appended lines with unique IDs taken like change numbers (highest ID on every `shipyard/*` branch, plus one); a merge conflict in memory is resolved by keeping both lines.
